# End-to-end acceptance procedures — revision 2

These procedures qualify the active plan; none has run in this planning session. The goal is actual Pantograph inference plus library-only Pumas RPC from an isolated frozen artifact. Preserve the producer, backend, runtime, artifact and desktop boundaries in every claim. Extend existing repository runners before adding evidence machinery.

## Record the actual candidate and environment

For every material run identify the Pantograph revision/dirty scope, current MCP runtime/content route, Pumas source/release/artifact digest and feature/target provenance, independent binary and writable-root paths, explicit endpoint and process ownership, model/library/artifact identities, Pantograph backend/runtime/dependency/device identities, trust and retention policy, exact command/procedure, result and deciding evidence. A health response or branch name is not identity/compatibility proof.

Keep one pinned producer during a run. Library artifact changes require deliberate selection and affected requalification. Build/type inputs must match the supported producer contract rather than the moving local Pumas checkout. Models come from qualified library assets; Pumas serving readiness is not an accepted precondition.

## B — Frozen library artifact and real RPC consumer (RPC-A00/01/02/03)

Compare the actual current upstream HEAD against 0.7.0 before selecting. Download and verify the candidate bytes or build a fixed commit independently, recording source/lock/toolchain/feature and output identity. Use an explicit isolated library root, database, registry/cache, endpoint and owned process. Prove from configuration/dependency resolution and exercised behavior that neither the active Pumas checkout/build output nor its development server is required. Do not disrupt the user's checkout to demonstrate independence.

Exercise Pantograph's real library client against this candidate for actual model discovery, selected descriptors, full facts, requirements/settings and executable asset resolution as needed. Follow the same values through preflight and dispatch to a Pantograph inference backend. Verify no embedded Pumas owner, direct private-database access, guessed root/path or silently selected alternative instance is used.

Test consumed success and failure contracts, malformed/wrong-type/oversized data, mismatched request/model/artifact/library identities, well-formed unsupported versions, unknown fields under the actual policy, explicit unavailable capability, service loss/replacement and cursor-gap recovery. Independent fixtures must isolate each intended negative condition. Real producer acceptance complements but does not replace negative contract tests.

## N — Pantograph-only inference (INF-A01)

Inspect construction, configuration, adapter selection and both single/batch execution to establish that every reachable Pantograph inference path uses its existing unified API and appropriate backend. Include pre-existing configurable compatible-provider routes that might otherwise point at the Pumas service. Reject/disable the forbidden Pumas execution selection under an explicit owning contract; do not remove legitimate non-Pumas backend support solely because endpoint path names overlap.

During the same real T/I/E workflow acceptance, observe all outbound calls to the configured Pumas fixture using existing request diagnostics, a claim-specific capture or a bounded test observer. Capture operation/route and necessary non-sensitive correlation only; do not export prompts, credentials or raw sensitive payloads. Assert that library reads and any explicitly admitted library effects are the only Pumas operations. There must be no Pumas `/v1` discovery/generation/embeddings, inference RPC, serving/profile startup, private provider or proxy inference calls.

Run the product path with Pumas inference features absent or demonstrably inactive. A library-only build is useful when supported, but the exact release candidate must still be exercised rather than replaced silently for the test. Observe actual Pantograph backend work/result and Pumas traffic together. A source grep, an assertion in a mock, or an idle library service is not proof that a real inference path respected the boundary. Match process-control evidence to the relevant provider owner and preserve unconfirmed-stop states.

## L — Lifecycle and failure

Preserve actual stop evidence and resource accounting. Time or silence alone does not kill a correctly running task. A disconnected observation or cancellation acknowledgement is not confirmed process/GPU completion. Do not automatically replay an uncertain inference effect.

Reject forbidden Pumas inference selection even when a compatible-provider configuration points there. Keep unrelated jobs/clients and the user's development services unaffected. Standard connection/control-operation bounds stay governed by their owners rather than inheriting inference lifetime rules.
